Prepared 14 October 2026. Read `VERIFICATION-REPORT.md` before deployment. This package contains the original multi-route Next.js website, the admin panel, the completed editing controls, approved portfolio data, local media, recovery tools and reproducible verification scripts. Historical notes are preserved in `docs/history`; their old percentages and build claims are superseded by the current report.

The latest UI/UX pass directly updates the shared header, typography, content layouts and contact form. On phones and tablets up to 800 pixels, the logo sits left, the three-line menu stays at the exact center of the visible page, and the CTA stays right. Appearance controls are inside the mobile menu. The header remains sticky and transitions from a blurred translucent surface to a more solid surface on scroll. Shared public readability/layout rules live in `app/public-ux.css`; component behavior stays in the existing components.

## Run locally

Use Node.js 20.9 or newer and install the locked dependencies with `npm ci`. Copy `.env.example` to `.env.local` and configure values privately. Run `npm run dev`, or `npm run build` followed by `npm start` for production. Public pages have approved content fallbacks and can render without a database; authentication, persistent editing, inquiries and uploads need the actual configured services.

For the restricted Windows filesystem used during this delivery, `npm run build:portable` applies a Windows filesystem compatibility shim and limits build workers. It still runs the normal Next.js SWC compiler, TypeScript and lint checks. Use `npm run build` on the deployment host.

## Database and admin

`db/schema.sql` defines the database. Preserve an existing database and review the schema against it before applying any setup SQL. Configure `DATABASE_URL`, a strong `AUTH_SECRET`, `BOOTSTRAP_SECRET` and the actual `APP_URL`. Open `/admin/login` and choose “Set up first Super Admin” for the protected initial bootstrap flow. Complete authenticator enrollment before the first owner login. The schema is byte-for-byte unchanged from the supplied ZIP; this release adds no Neon schema migration. Existing databases must already match that schema. Never put secrets in the source archive or public settings.

Use `/admin/design` to edit the original website through its authenticated iframe preview. Select an element for small Edit, Hide, Delete, Create and ordering controls. Double-click text to type directly. Advanced image, button-link, typography, color, spacing, alignment, position and responsive controls appear under Edit. Hidden and deleted elements can be restored. The preview fits real desktop, tablet or mobile page widths inside the workspace. Alt-click a link to navigate the preview. Menu, footer, floating contact and page copy controls are also available in the inspector. Save draft is private; Publish changes needs publishing permission. Autosave, undo/redo, revisions and concurrent-edit protection are included.

Use `/admin/pages` for section layouts and nested containers, headings, text, images, buttons, spacers and dividers. The canvas supports selection, section ordering and nested sibling ordering, including keyboard alternatives. Use Content library for services, projects and articles, including the original eight services, four articles and 38 projects without a manual import. Edit, Hide/Show, Delete/restore and New actions are alongside each record. A hidden or archived default stays hidden on public listings and detail routes. New services receive working detail routes. Use Structure for the optional topbar, header, navbar and footer, and Theme for site appearance. The shared admin topbar has a visible appearance switch. Use Media for uploaded assets; Users for granular roles; Approvals for review; Operations for content exports.

## Integrations

Cloudinary needs its three private environment values. Uploads accept validated raster formats and include image crop controls. Resend needs an account, an API key and a verified sender; its account has not been created for this delivery. Without Resend, persisted inquiries remain accessible to admins and email failure is recorded. Without a database, the form reports unavailability rather than a false success. WhatsApp and Calendly destinations are editable settings. Analytics/object-storage variables in the historical template are not evidence of configured services.

## Backups and recovery

Admin content export is a checksummed content export, not a complete database backup. It excludes private security and design-draft settings. Validate with `npm run verify:export -- <export.json>`. The merge-only restore script defaults to offline validation; database writes require both `--apply --confirm-merge`.

For a full database archive, inject `DATABASE_URL` securely and run `npm run backup:db -- <private-directory>`. PostgreSQL client tools matching the hosted database are required. A full restore requires the checksum sidecar, a successful pre-restore backup and `VELAUR_CONFIRM_RESTORE=RESTORE_AND_REPLACE_TARGET_DATABASE`; then run `npm run restore:db -- <archive.dump>`. Test this on staging before a production recovery. Cloudinary binaries, hosting settings and secrets need separate protected backups. Schedule the local backup command on an approved trusted runner; no production schedule or external backup destination is active in this package.
